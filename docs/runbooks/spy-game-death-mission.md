# Смертельная операция: all-in и личная миссия

Реализовано локально. Проверка в реальном Telegram и production rollout ещё
не выполнены. Изменения включаются для новых событий отдельным флагом.

## Новые операции: roguelite_v4

Ставка **сохранена всей доступной сетью** в обоих режимах. Ограниченного отряда
и выбора отдельных агентов нет. Перед arm и commit сервер снова сверяет состав;
изменившаяся сеть требует нового подтверждения. Новые агенты после commit
не входят в резерв и не теряются при поражении.

V4 применяется только к новым preview. Открытые preview/armed/in_run v1/v2/v3
сохраняют прежние числа, предложения, траектории и выплаты. Общая проверка
доступности и исправленные подсказки работают для всех версий.

| Что изменилось | V4 |
|---|---|
| Урон осложнения на узлах 1–5 | 2 / 2 / 2 / 3 / 3 |
| Минимальный риск на узлах 3–5 | 5 / 15 / 20%; «Тихий вход» уменьшает ещё на 3 п.п. |
| Победа личной миссии | Для каждого типа `floor(amount × 6 / 5)`; ещё один Tier 3/4 при доступном выбранном бонусе |
| Порог бонуса личной миссии | 8 агентов выбранного Tier или выше в зафиксированной ставке |
| All-in | Без изменений: стандартные 35%, ×2, Tier 3 ×1 |
| Саботажник в ставке | Один заряд: −10 п.п. риска прорыва из засады или в фазах 1–2 финала |
| Агент-призрак в ставке | Один заряд: −15 п.п. для Подготовленного прохода/Коллектора в фазе 3 финала |
| Архив | Схема 4×4 перед обычным действием: 8 соседних ходов, +1 разведданное при решении; пропуск/неудача без штрафа |
| Защита | Щит «Штурма» сохраняется, если броня поглотила весь урон; Аварийный канал исключён из второго слота |

Несколько одинаковых специалистов не увеличивают заряд. Применение — отдельное
действие; риск уменьшается после остальных модификаторов и нижней границы.
Заряд расходуется при любом исходе. Специалист остаётся частью общей ставки.
Пулы стандартных обменов не меняются.

HTML5 показывает карту с пройденными комнатами и скрытыми будущими узлами,
рисунки комнат, отдельные фазы финала, заряды и схему Архива. Подробности исходов
и журнал можно раскрыть. Telegram fallback поддерживает те же действия,
специалистов и схему с кнопками координат. Сервер хранит все ходы; клиент не
может прислать «победа» или готовую оценку головоломки.

### Процентное раскрытие исхода

После рискованного действия HTML5 показывает шкалу 1–100: красная область
`1…risk` означает осложнение, зелёная `risk+1…100` — отсутствие осложнения.
Бросок раскрывается за 0,85 секунды, затем показываются изменения ресурсов,
поглощённый урон, медик, пропуск и облава. Через секунду открывается следующий
экран. Кнопка «Показать результат сразу» пропускает анимацию; при системном
уменьшении движения результат сразу доступен без промежуточного экрана.

Результат хода уже сохранён до начала анимации. Повтор запроса использует тот же
`operation_id`; перезагрузка показывает сохранённый бросок без повторной анимации.
Последняя проверка доступна в раскрываемом блоке и на итоговом экране, остальные
броски — в журнале. Telegram получает число в описании принятого действия.
Для all-in показывается та же шкала с зонами проигрыша и выигрыша.

Это только представление существующих правил, без d20 и критических исходов.
В журнал рискованного хода добавлено поле `roll = исходный_бросок + 1`; all-in
отражает свой исходный бросок как `100 − исходный_бросок`, чтобы высокие значения
также означали успех. Seed, ключ броска, вероятности, последствия и выплаты не
изменены. Старые записи без `roll` продолжают отображаться текстом. Миграция
не требуется. Сохранённые до изменения хеши траекторий v1–v4 проверяются
в `tests/test_death_mission_rolls.py` без нового поля представления.

### Постоянная тренировка

В Центре доступна «Тренировка операции» без события и наличия агентов.
Она использует тот же движок v4, тактику «Баланс», обоих виртуальных специалистов
и гарантированный Архив среди первых двух комнат. У неё отдельные таблицы
`death_mission_practice` и `death_mission_practice_actions` из миграции
`020_death_mission_practice.sql`. Она не создаёт `game_events`, резерв, выплаты,
экономические достижения или сообщения в чат.

Одна активная тренировка на пользователя, 15 минут без продления при reopen;
продолжение ротирует bearer token. Для запуска нужен авторизованный участник
доступного чата. `POST /spy-app/api/death/practice` возвращает URL с токеном;
последующие чтения и действия используют существующий game API. Общий выключатель,
allowlist и отключение чата закрывают доступ. Отдельный флаг Death Roguelite
по-прежнему регулирует создание событий, а не возможность обслужить старый run.

### Исправления доступа и локальная проверка

Сохранённые токены больше не обходят `settings.enabled`, allowlist и выключение
чата. Проверка выполняется в транзакции до нового резерва; активная ставка
возвращается ровно один раз. Подсказки учитывают Глушитель, использованный
Поддельный пропуск и актуальные ветки защиты.

Для нового баланса DP учитывает весь маршрут, эвакуацию, заряд каждого
специалиста и умение решать схемы. Проверяются все четыре состава поддержки,
идеальное решение и полный пропуск схем, отдельные реальные составы сети.
При пороге бонуса 8 максимальный относительный возврат за победу ограничен
`1,2 + 1/8 = 1,325` ставки при любых положительных неубывающих весах Tier;
округление и состав бонуса могут его только уменьшить. Поэтому верхняя DP-оценка
применима и к большой сети. Гейт ожидаемого полного возврата остаётся 1,15.

**Результат 2026-09-22:** [полный отчёт v4](../ideas/spy-game-death-mission-balance-v4.json),
57 случаев по 10 000 seed, всего **570 000 забегов**. Гейт пройден: максимальная
точная DP-оценка **1,1066593558**, худшая эмпирическая полная выплата **1,082738**,
её 95%-интервал **[1,073566; 1,091909]**. Худший случай — «Штурм» с обоими
специалистами и верхней оценкой бонуса. Предел 1,15 допускает рост сети;
это не доказательство отсутствия инфляции. Все значения относятся к стандартным
пулам бонусов; изменённые пулы требуют отдельного пересчёта.

Вероятность победы в контрольных симуляциях **без специалистов**, с решением
схем Архива (политики используют только публичные данные):

| Тактика | careful | informed | strong | Эвакуация strong |
|---|---:|---:|---:|---:|
| Баланс | 39,67% | 54,28% | 56,85% | 25,19% |
| Тихий вход | 44,04% | 53,52% | 63,52% | 18,08% |
| Штурм | 51,12% | 61,52% | 69,76% | 21,33% |

Для сравнения: в отдельной проверке v3 «Баланс»/informed давал 31,8% побед.
Это сравнение симуляций на разных фиксированных наборах seed, не A/B-тест игроков.
`strong` максимизирует выплату с учётом эвакуации, а не частоту побед.

Локальные проверки: **423 Python-теста**, **29 JS-проверок**, настоящий Chrome
на 300/320/360/390/480/760 px. Проверены карта, схема, практика, оба режима
подтверждения, финал, недоступная способность, эвакуация и терминальный экран.
Эталонный хеш 300 траекторий v3 сохранён. Миграция, рестарт, повтор хода/выплаты,
одновременный commit, закрытие доступа и выигрыш тренировки проверены на временной
SQLite. Две картинки выше получены тем же браузерным тестом.

## Архив правил v3

Следующие правила и баланс описывают сохранённые забеги v3.

На входе доступны два режима. В обоих ставка — вся **доступная** сеть агентов,
без предметов и экипировки. Перед списанием показывается точный состав и
отдельное подтверждение. В HTML5 кнопку подтверждения нужно удерживать 3 секунды.

| Режим / исход | Возврат поставленных агентов | Бонус |
|---|---|---|
| All-in: мгновенный успех с вероятностью 35% | Каждый тип ×2 | Один случайный Tier 3 |
| All-in: провал | 0 | Нет |
| Личная миссия: полный финал | Каждый тип ×2 | Один выбранный Tier 3 или Tier 4, если в ставке минимум 5 агентов этого тира или выше; иначе без бонуса |
| Личная миссия: эвакуация | Половина каждого типа с округлением вниз | Нет |
| Личная миссия: гибель / сдача | 0 | Нет |
| Таймаут личной миссии | Половина, если эвакуация уже открыта; иначе 0 | Нет |
| Административная или техническая отмена | Исходная ставка целиком | Нет |

Личный маршрут: пять обычных узлов, затем финальный объект из трёх фаз.
«Баланс» начинает с состояния 6, разведданных 2 и тревоги 0. «Тихий вход» —
с 5/2 и снижением риска на 3 п.п.; «Штурм» — с 6/0 и поглощением первого урона.
Убежище гарантировано на узле 2. На узлах 4–5 доступны только Патруль,
Архив, Двойной агент и Засада.

В v3 каждое действие на узлах 3–5 имеет риск не ниже 10/30/40% (у «Тихого
входа» на 3 п.п. меньше), урон осложнения на этих узлах — 3/4/5. Платные
обходы также могут осложниться. Финал наносит 3/3/4 урона по фазам;
«Прорываться» имеет базовый риск 45% и добавляет 2 тревоги.
При тревоге 6 облава наносит ещё 2 урона и снижает тревогу до 4.
Нулевое состояние сразу завершает забег, в том числе в последней фазе.

После узлов 1 и 3 выдаётся один из трёх предложенных модулей. Полевой медик
лечит выжившую группу между фазами финала; пропуск отменяет первую облаву и
уменьшает урон последующих на 1. Эвакуация доступна после узла 3, с Аварийным
каналом — после узла 2. Она возвращает половину каждого типа с округлением вниз.

Вся награда показывается до arm/commit. Для бонуса v3 учитывается именно
состав ставки: пять агентов нужного тира или выше. Новые поступления после
commit не открывают бонус задним числом. Недоступный бонус отклоняется сервером.
Режим без дополнительного агента доступен с любой ненулевой ставкой.

`roguelite_v1` и `roguelite_v2` сохранены с исходными числами и бонусами
(Tier 3 ×2 либо Tier 4 ×1 без порога). Версия фиксируется при первом создании
preview, поэтому уже открытые подтверждения и начатые забеги не переводятся
на v3. Ранее сыгранные траектории v1/v2 проверяются по эталону коммита 152ee01.

В интерфейсе процент до финала означает только «если попасть на финал сейчас»,
а не шанс всего оставшегося маршрута. У модулей он не учитывает будущие
комнаты и раннюю эвакуацию. Флаги уже использованной защиты публичны; seed и
будущие комнаты остаются только на сервере.

Постоянный архив: три забега с пройденным узлом 3 открывают «Тихий вход»;
пережитая облава и пройденный узел 3 в одном забеге открывают «Штурм».
Дальнейшая гибель не отменяет этот прогресс. Технический возврат его не даёт.
Модули между забегами не сохраняются. Начать миссию можно только один раз
на событие; один пользователь не может одновременно поставить сеть в другом чате.

Срок личной миссии — 15 минут после commit. Срок не продлевается при reopen.
Закрытие окна не останавливает таймер. Повторный запуск из Telegram и обновление
HTML5 восстанавливают состояние; в браузере токен хранится только в sessionStorage.
Повторный вход из Telegram ротирует токен и может отключить старую вкладку.

Агенты на операции показаны отдельно в Mini App и Telegram-списке сети.
Обмены и дуэли работают с оставшимся доступным балансом. Новые поступления
во время забега не входят в его ставку и не теряются при его провале.

## Баланс и воспроизводимость

Числа v3 настроены на `tuning-v3`, затем проверяются на отдельном наборе
`validation-v3-20260921`. Оба набора фиксированы. При изменении правил,
множителя или бонусов отчёт надо пересчитать; здесь проверены стандартные ×2,
35% для all-in и стандартные пулы Tier 3/4.

[Полный отчёт v3](../ideas/spy-game-death-mission-balance-v3.json) включает
по 10 000 забегов на каждую комбинацию тактики, политики и экономического
сценария: всего 360 000 забегов. Политики: random, aggressive, careful,
informed (прежняя эвристика по финалу) и strong.

`strong` — offline DP по **всему маршруту**, максимизирующее ожидаемую выплату.
Она учитывает эвакуацию на каждом шаге, стоимость конкретного бонуса и
округление возврата ставки. Неизвестные комнаты и модули усредняются по
распределению предложений; seed, скрытая карта и будущий бросок ей не доступны.
Расчёт использует тот же `resolve()`, что runtime, и не вызывается в HTTP-запросах.

Отчёт показывает смерти по узлам и причинам, частоты действий, обе цели финала,
сборки модулей, распределения ресурсов на входе в финал и длительность в ходах.
Экономические случаи: один Осведомитель, малая смешанная сеть, редкая сеть и
большая сеть, каждый доступный бонус. Нулевой бонус при доступном бесплатном
дополнительном агенте заведомо хуже и отдельно не оптимизируется.
Точные возвращённые агенты и бонусы считаются общей с SQLite settlement
функцией; приведены количества по типам и Tier, включая чистое создание/сжигание.

Аналитические веса Tier 1–6 заранее зафиксированы: 1, 4, 16, 64, 256, 1024.
Это не внутриигровой курс обмена. Дополнительно проверяется `all_stakes_bound`:
один бонус при пяти агентах того же или более высокого тира стоит не больше
0,2 стоимости ставки при **любых положительных неубывающих весах Tier**.
Поэтому полная победа ограничена 2,2 ставки, эвакуация — 0,5. DP оптимизирует
и этот более выгодный гипотетический режим: он даёт верхнюю оценку для любых
составов, в том числе не включённых в примеры.

**Гейт:** полная ожидаемая выплата, включая бонус, не выше 1,15 стоимости
ставки. Требуются минимум 10 000 seed на случай, полное покрытие экономических
сценариев, верхняя граница 95%-интервала каждого случая ≤1,15 и точная DP-оценка
для каждого объекта финала ≤1,15. Интервалы приближённые, для отдельных случаев,
не совместный доверительный интервал. Модель предполагает равномерные независимые
броски и предложения, как расчёт финала; реальные seed проверяются симуляцией.
Допуск 1,15 допускает рост сети — это не доказательство отсутствия инфляции.
All-in показан отдельной исторической базой и этим гейтом не регулируется.

Результат проверки 2026-09-21: **гейт пройден**. Максимальная точная
верхняя оценка полной выплаты — **1,130245** ставки (Штурм, Бронепоезд,
`all_stakes_bound`). Наибольшая эмпирическая оценка среди проверок гейта —
**1,09665**, её 95%-интервал **[1,077098; 1,116202]**. Обе границы ниже 1,15.

Контрольная сильная политика с целью «возврат ставки», без бонуса в целевой
функции (экономические случаи с конкретными бонусами оптимизируются отдельно):

| Тактика | Победа | Эвакуация | Смерти до финала / все смерти |
|---|---:|---:|---:|
| Баланс | 35.59% | 35.61% | 563/2880 |
| Тихий вход | 44.09% | 20.08% | 819/3583 |
| Штурм | 43.39% | 29.10% | 934/2751 |

У этой политики до финала произошло 2316 из 9214 смертей, **25,14%**.
Случайная политика не считается моделью обычного игрока; осторожная и прежняя
informed-политика также сохранены в отчёте для сравнения.

```bash
.venv/bin/python -m spy_game.death_mission_simulation \
  --version roguelite_v3 --runs 10000 --seed validation-v3-20260921 \
  > docs/ideas/spy-game-death-mission-balance-v3.json
```

Прогресс идёт в stderr; JSON — в stdout. Код выхода 0 означает пройденный гейт,
1 — провал, недостаточную выборку или неполный прогон (`--no-economy`).
Исторический [отчёт v1](../ideas/spy-game-death-mission-balance-v1.json) получен
старой версией симулятора и служит архивом, а не актуальной проверкой v3.
У v3 тренировочного UI не было. Постоянная тренировка v4 описана выше;
offline-симулятор по-прежнему не использует базу или настоящие награды.

## Включение и dev-проверка

Настройки нового функционала:

```dotenv
SPY_GAME_DEATH_ROGUELITE_ENABLED=true
SPY_GAME_DEATH_MISSION_SECONDS=900
```

По умолчанию первый флаг `false`. Он выбирает `config_id=death_choice_v1`
только для новых событий. Уже созданные `all_in_v1` продолжают старую механику.
Для HTML5 используются существующие `SPY_GAME_WEBAPP_ENABLED`,
`SPY_GAME_HTML5_URL` и short name `spies`. Без HTML5 работает тот же движок
через inline-кнопки. У HTML5-публикации также есть кнопка «Текстовый режим».

В dev-чате с разрешённым manual spawn:

```text
/spy_admin enable
/spy_admin spawn death_operation
```

Проверить двумя аккаунтами:

1. Открыть выбор: all-in и миссия, состав, закрытые/доступные бонусы и вариант
   без бонуса. Проверить границу 7/8 подходящих агентов в v4 (4/5 в v3) и отмену подтверждения.
2. Начать миссию первым аккаунтом, попытаться начать all-in вторым: второй
   не теряет агентов. В другом чате тот же первый пользователь не начинает новый run.
3. Пройти комнату в HTML5, затем продолжить текстовыми кнопками. Проверить
   восстановление через повторный вход и после перезапуска сервиса.
4. Проверить эвакуацию, полный финал, таймаут и отключение чата с возвратом ставки.
5. Проверить обновление исходного сообщения итогом и отсутствие повторной награды.

Итоги доставляются persistent outbox через редактирование исходного сообщения,
включая Game message; это поддерживает
[Telegram editMessageText](https://core.telegram.org/bots/api#editmessagetext).
Повторная доставка повторяет редактирование, а не отправляет новый пост.

## Хранение и эксплуатация

Миграция `013_death_mission.sql`: runs, неизменяемая ставка, reserve/settle
ledger, журнал idempotency, достижения и outbox. В SQLite сохраняется только
hash launch-токена. Скрытые seed/карта не входят в публичный API.

Мутации HTTP: `/spy-app/api/game/death/{arm,back,commit,action,extract,abandon}`.
Каждая принимает `revision`, `operation_id`, `choice`; `commit` относится к
выбранному и подтверждённому режиму. Состав повторно сверяется непосредственно
перед резервированием. Смена состава возвращает `STALE_STAKE` без списания.

SQL-аудит на **копии или через read-only подключение к нужной базе**:

```sql
SELECT status, mode, COUNT(*) FROM death_mission_runs GROUP BY status, mode;

-- После остановки новых запусков и завершения миссий должно быть 0.
SELECT COUNT(*) FROM death_mission_runs WHERE status = 'in_run';

-- Для каждого закрытого резерва должна существовать единственная settlement.
SELECT r.id, r.status FROM death_mission_runs r
JOIN death_mission_ledger reserve ON reserve.run_id=r.id AND reserve.action='reserve'
LEFT JOIN death_mission_ledger settlement
  ON settlement.run_id=r.id AND settlement.action='settle'
WHERE r.status != 'in_run' AND settlement.run_id IS NULL;

-- Недоставленные итоги: сеть/удалённое сообщение требуют проверки.
SELECT run_id FROM death_mission_outbox WHERE delivered_at IS NULL;
```

Перед host rollout — online backup SQLite через `.backup` и
`PRAGMA integrity_check`, как в [общем runbook](spy-game-server-rollout.md).
Первое включение — один allowlisted beta-чат. Этот документ не означает,
что rollout или публичный HTTPS smoke уже выполнены.

Отключение `SPY_GAME_DEATH_ROGUELITE_ENABLED` останавливает создание новых
событий с выбором, но уже созданные события и активные миссии обслуживаются.
Для срочного возврата ставки master выключает соответствующий чат через
`/spy_admin disable`: возврат и история записываются атомарно. Старый бинарник
допустим только после завершения или возврата всех резервов. Миграции не удалять.

Локальная проверка:

```bash
.venv/bin/python -m pytest -q
node --test tests/test_death_mission_ui.js
node --check spy_game/webapp_static/death.js
CHROME_BINARY="/path/to/chrome" node --test tests/test_death_mission_browser.js
```

Браузерный тест запускает отдельный headless Chrome с временным профилем,
без подключения к боту. Он проверяет CSS и ширины 300–760 px, панель эвакуации
и скрытие завершённой миссии. Нужны Node с WebSocket/fetch и локальный Chrome;
без `CHROME_BINARY` тест явно пропускается. JS unit-тесты отдельно воспроизводят
задержавшийся polling после новых ревизий и сброс устаревшего подтверждения.
При публикации обновлять HTML, CSS и death.js вместе: версии assets повышены до 4.
