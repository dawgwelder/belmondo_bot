# Ревью кода и аудит проекта Belmondo Bot

Дата оформления: 5 сентября 2026 года.

Документ фиксирует результаты предыдущего локального аудита рабочей копии,
включая новые игровые режимы. При оформлении отчёта повторные проверки не
выполнялись. Указанные номера строк соответствуют просмотренной версии файлов.
В ходе аудита код не изменялся, коммиты не создавались.

## Результат

Выявлено 7 проблем. Первые три рекомендуется устранить до следующего релиза.

- **P1** — высокий приоритет: ограничения доступа и доступность приложения.
- **P2** — следующий приоритет: игровая логика, зависимости и жизненный цикл.

## 1. [P1] Глобальное отключение игры не запрещает списание агентов в Death Mission

**Код:** [spy_game/service.py](../spy_game/service.py), строка 456,
`mutate_death_mission`.

Для сохранённой сессии отсутствуют проверки `settings.enabled` и allowlist.

**Воспроизведение на временной базе:**

1. Открыть предварительный просмотр миссии и сохранить токен.
2. Перезапустить сервис с `SPY_GAME_ENABLED=false`.
3. Выполнить `arm` и `commit` с сохранённым токеном.

Миссия переходит в `in_run`, баланс уменьшается с 6 до 0. Запрос состояния
возвращает HTTP 200. Удаление чата из allowlist также не препятствует операции.

**Последствие:** административное отключение не блокирует новые списания
по ранее открытым сессиям.

**Рекомендация:** проверять доступ перед новым резервированием ставки.
Отдельно определить порядок завершения и возврата уже зарезервированных ставок.
Это не замечание к флагу `SPY_GAME_DEATH_ROGUELITE_ENABLED`: сохранение обслуживания
существующих событий после отключения этого флага предусмотрено runbook.

## 2. [P1] Долгий AI-запрос задерживает Telegram-события во всех чатах

**Код:** [app.py](../app.py), строка 100;
[handlers/ai.py](../handlers/ai.py), строка 78.

Приложение создаётся с последовательной обработкой обновлений:
`max_concurrent_updates = 1`. AI-обработчик ожидает весь ответ модели внутри
обработки одного обновления.

**Проверка:** в локальном приложении без сетевых вызовов второй update
не обрабатывался, пока первый обработчик ожидал завершения операции.
После освобождения первого обработчика второй update был обработан.

**Последствие:** ответ модели в одном чате задерживает команды и игровые
callback-запросы в остальных. За время ожидания игровые действия могут просрочиться.

**Рекомендация:** вынести длительные операции в управляемые фоновые задачи,
сохранив блокировки состояния. Простое включение общей конкурентной обработки
требует отдельной проверки гонок в существующих обработчиках.

## 3. [P1] Неавторизованные запросы могут неограниченно увеличивать потребление памяти

**Код:** [spy_game/webapp.py](../spy_game/webapp.py), строка 140,
`_RateLimiter`; строка 745, `_limit_game_mutation`.

Ограничитель сохраняет ключи бессрочно. Устаревшие отметки времени очищаются
только при обращении к тому же ключу, сами ключи не удаляются. Игровые endpoints
вызывают ограничитель до проверки токена: каждый новый произвольный токен
создаёт отдельную запись.

**Проверка:** после добавления 10 000 различных ключей и продвижения модельного
времени на час все записи сохранились. После запроса с ещё одним ключом размер
словаря составил 10 001.

**Последствие:** невалидные запросы могут накапливать записи в памяти процесса
бота. Падение от исчерпания памяти нагрузочным тестом не проверялось.

**Рекомендация:** ограничить размер хранилища, удалять устаревшие ключи и
предусмотреть ограничение запросов до авторизации. Для авторизованных игровых
действий использовать проверенную идентичность сессии или пользователя.

## 4. [P2] В «Перехвате» можно получить награду без прохождения игры

**Код:** [spy_game/webapp.py](../spy_game/webapp.py), строка 767,
`_intercept_game_payload`;
[spy_game/repositories.py](../spy_game/repositories.py),
`finish_intercept_game`.

API отправляет клиенту точные `targets`. При завершении сервер сравнивает их
с присланными клиентом `locks`.

**Воспроизведение:** сразу после запуска отправить `locks = targets`.
При одинаковом серверном времени запуска и завершения получены:

- статус `won`;
- 5000 очков;
- награда `access_code ×1`.

**Последствие:** клиент может гарантированно завершить игру с максимальным
результатом без выполнения действий интерфейса.

**Рекомендация:** изменить протокол так, чтобы сервер проверял последовательность
игровых действий. Одного пересчёта присланного результата недостаточно.

## 5. [P2] Парсинг гороскопов требует отсутствующей зависимости

**Код:** [horoscope.py](../horoscope.py), строка 140;
[requirements.txt](../requirements.txt).

Используется `BeautifulSoup(..., features="lxml")`, но `lxml` не указан в
зависимостях. Для Beautiful Soup он является необязательной зависимостью.

**Воспроизведение:** вызов `_fetch_page` с подставленным корректным HTML
в проверенном Python-окружении завершился ошибкой:

```text
FeatureNotFound: Couldn't find a tree builder with the features you requested: lxml.
Do you need to install a parser library?
```

**Последствие:** установка зависимостей из `requirements.txt` не обеспечивает
работу парсера гороскопов. Успешный `pip check` этот дефект не обнаруживает.

**Рекомендация:** явно добавить зависимость или использовать доступный парсер,
проверив извлечение текста на характерных HTML-страницах.

## 6. [P2] Остановка Telegram-приложения пропускает updater.stop()

**Код:** [app.py](../app.py), строка 239.

После запуска polling блок завершения вызывает `application.stop()` и
`application.shutdown()`, но не вызывает `application.updater.stop()`.

**Проверка установленной библиотеки:** `Application.stop()` не останавливает
updater. Его `shutdown()` выбрасывает `RuntimeError`, если updater ещё работает.

**Последствие:** нарушается корректное завершение polling и освобождение ресурсов.

**Рекомендация:** останавливать работающий updater перед остановкой и shutdown
приложения; учитывать частичную инициализацию при ошибках запуска.

## 7. [P2] Зафиксированная версия aiohttp содержит известную уязвимость

**Код:** [requirements.txt](../requirements.txt), строка 4;
[horoscope.py](../horoscope.py), строки 114 и 135.

В зависимостях и проверенном окружении установлена версия `aiohttp==3.12.15`.
Она входит в диапазон версий, затронутых CVE-2026-69244: некорректный HTTP-ответ
может вызвать отказ клиентского процесса в C-парсере. Клиент aiohttp используется
загрузчиком гороскопов.

Согласно [официальному advisory GHSA-cq5v-8q36-5273](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-cq5v-8q36-5273),
затронуты версии `<=3.14.2`, исправление опубликовано в `3.14.3`.
Эксплуатация уязвимости на проекте не воспроизводилась.

**Рекомендация:** обновить зависимость до версии с исправлением и проверить
совместимость HTTP-клиента и Web App. Проверка этого advisory не заменяет
полное сканирование всех зависимостей.

## Архитектура и сопровождение

Постоянная экономика имеет хорошую основу: SQLite-транзакции, уникальные
ограничения, история операций и проверки повторных действий.

Основной архитектурный долг — разросшиеся модули:

- `spy_game/repositories.py` — около 4100 строк;
- `handlers/spy_game.py` — около 2500 строк.

Проверки доступа уже расходятся между режимами. Рекомендуется централизовать
эти проверки и постепенно разделять код по игровым сценариям, сохраняя общую
транзакционную границу экономики.

В просмотренной рабочей копии не обнаружена конфигурация CI. Настройки
pre-commit также требуют согласования: Black настроен на целевой Python 3.6,
а mypy — на Python 3.10. Локальные проверки аудита выполнялись на Python 3.12.4.

## Ограничения аудита

- Проверки выполнялись локально с временными базами и подставленными сетевыми
  ответами.
- Production, реальные Telegram-сценарии и конфигурация nginx/TLS не проверялись.
- Восстановление серверной базы из backup не выполнялось.
- Полное CVE-сканирование зависимостей и нагрузочное тестирование не проводились.
- Документ фиксирует найденные проблемы; их исправление в рамках аудита
  не выполнялось.
