# HTML5-игры «Найти крота» и «Смертельная операция»

Статус: «Найти крота» и выбор all-in / личной Смертельной операции реализованы
локально. Production rollout и Telegram smoke не выполнены. Актуальный контракт
Смертельной операции — в [runbook](../runbooks/spy-game-death-mission.md);
описанный ниже первоначальный preparation-only вариант не является текущей реализацией.

Развитие Смертельной операции в roguelite описано отдельно:
[Death Mission: маршрут, сборка и эвакуация](spy-game-death-mission-roguelite-plan.md).
Это предложение версии `roguelite_v1`, которое заменяет контракт подготовки
из раздела 2.2 при выборе нового режима. Ниже сохранён исходный вариант с
фиксированными 35%; смешивать его правила расчёта с roguelite нельзя.
В коде событие называется `death_operation`; `death_mission` — название концепции.

Цель — добавить две механики в существующую Telegram HTML5 Game `spies`, не
создавая отдельный процесс или вторую базу. Экономика, таймеры, победители и
награды остаются серверными и хранятся в SQLite через `SpyGameService`.

## 1. Отправная точка

- «Поиск крота» сейчас существует как сюжетная арка `mole_hunt`, но не как
  отдельное игровое событие.
- «Смертельная операция» уже работает в Telegram как all-in: два нажатия для
  подтверждения, шанс успеха 35%, при успехе состав возвращается в двойном
  количестве и выдаётся случайный агент Tier 3, при провале теряются все
  агенты.
- HTML5-игра `spies` уже обслуживает «Перехват» и «Тайник» через тот же
  `belmondo.service`, HTTP listener и SQLite.
- Для обеих новых игр нужно сохранить Telegram inline fallback.

## 2. Предлагаемые игровые контракты

| Параметр | Найти крота | Смертельная операция |
|---|---|---|
| Формат | Дедуктивное дело | Подготовка и all-in запуск |
| Время | 5 минут | 2 минуты на подготовку |
| Задача | Изучить четыре досье и улики, выбрать крота | Подготовить внедрение, связь и эвакуацию |
| Попытки | Одна финальная версия от игрока | Подготовку можно исправлять до подтверждения |
| Ошибка | Завершает личную сессию, событие остаётся другим | До финального commit агенты не теряются |
| Победа | Первый правильный ответ закрывает событие | Первый подтверждённый запуск рассчитывает событие |
| Экономика | Случайный предмет x1 и Осведомитель x3 | Текущие 35%, состав x2 и бонус Tier 3 |
| Роль AI | Атмосфера и финальный текст | Атмосфера и финальный текст |

### 2.1. Найти крота

Игровой цикл:

1. Игрок получает четыре досье подозреваемых.
2. Открывает серверные фрагменты: маршрут, алиби, канал связи и замеченное
   противоречие.
3. Сопоставляет факты.
4. Делает одно окончательное обвинение.
5. Первый правильный ответ получает награду и закрывает событие для чата.

Дело генерируется сервером из конечного набора проверенных шаблонов. Каждый
шаблон обязан иметь ровно одно решение. Порядок карточек можно перемешивать для
каждого игрока, но идентификаторы подозреваемых и правильный ответ остаются
серверными.

Неправильное обвинение завершает только личную сессию. Другие участники могут
продолжить расследование. Повторное обвинение от того же игрока не принимается.

Награда первого релиза — один случайный предмет из текущего реестра и три
агента Tier 1 (`informant`, «Осведомитель»). Бесплатный Tier 3 не добавляется,
чтобы не обесценить существующие рецепты Контрразведки.

Интеграция с сюжетом:

- добавить `event_type="find_mole"`;
- разрешить естественный spawn только в арке `mole_hunt` на стадиях 3 и выше;
- на третьей стадии использовать событие как гарантированную кульминацию, а
  после неё возвращать его в обычный взвешенный пул;
- успешное раскрытие переводит историю на stage 4;
- успешное раскрытие на stage 4 и выше не меняет уже пройденную сюжетную стадию;
- на первом релизе сохранить прежнее завершение через NPC как совместимый
  fallback;
- добавить `/spy_admin spawn find_mole` для dev и beta smoke.

Telegram fallback показывает краткие улики и четыре inline-кнопки
подозреваемых. Правильность ответа проверяет тот же repository use case, что и
HTML5.

### 2.2. Смертельная операция

В первом HTML5-релизе вероятность и награда не меняются. Игровая часть делает
all-in осознанным и защищает игрока от случайного списания, но не скрывает и не
подкручивает шанс успеха.

Игровой цикл:

1. Сервер фиксирует снимок текущей агентурной сети игрока.
2. Экран показывает полный список агентов, которые окажутся на кону, и честный
   шанс успеха 35%.
3. Игрок собирает план из трёх этапов: внедрение, связь, эвакуация.
4. После подготовки открывается отдельный экран необратимого подтверждения.
5. Игрок удерживает кнопку запуска 2–3 секунды.
6. Сервер повторно проверяет снимок сети и атомарно рассчитывает операцию.

Если состав агентов изменился, сервер возвращает `STALE_STAKE`, показывает
обновлённый состав и требует пройти подтверждение заново. Таймаут, закрытие окна
или ошибка до финального commit не списывают агентов.

Финальная транзакция сохраняет существующий порядок:

1. Проверить чат, событие, срок, участника и снимок ставки.
2. Атомарно забрать активное событие.
3. Обнулить поставленные типы агентов.
4. Выполнить серверный roll.
5. При успехе вернуть каждый тип x2 и добавить случайного агента Tier 3.
6. Записать единственную строку `event_history`.
7. Вернуть уже сохранённый результат браузеру и Telegram handler.

Во второй версии можно исследовать влияние качества подготовки на вероятность,
но только после beta-статистики и отдельного моделирования экономики.

## 3. Общий HTML5-контур

### 3.1. Запуск игры

- Сохранить одну Telegram Game с short name `spies` и URL `/spy-app/game/`.
- Добавить фасад `start_html5_game(chat_id, message_id, user)`, который сначала
  определяет тип события по серверным данным, затем создаёт соответствующую
  сессию.
- Убрать последовательную эвристику «попробовать открыть Перехват, затем
  Тайник» до добавления третьего и четвёртого типа игры.
- Сохранить непрозрачный bearer-токен во fragment URL; в SQLite хранить только
  его hash.

### 3.2. Frontend

Разделить текущий `game.js` на общий runtime и игровые модули:

- загрузка state, bearer header, таймер, ошибки и итоговый экран;
- `intercept`;
- `dead_drop`;
- `find_mole`;
- `death_operation`.

Общий runtime не должен принимать решений об исходе, награде, сроке или
доступности действия. После каждого существенного действия он перечитывает
авторитетное серверное состояние.

### 3.3. HTTP API

Сохранить:

```text
GET /spy-app/api/game/state
```

Добавить явные мутации:

```text
POST /spy-app/api/game/mole/accuse
POST /spy-app/api/game/death/prepare
POST /spy-app/api/game/death/commit
```

Каждая мутация принимает revision или idempotency key. В ответах запрещено
возвращать правильного подозреваемого, серверный random roll, Telegram user ID,
секретный token или скрытые поля сценария.

## 4. Persistent-модель

### 4.1. Миграция `012_find_mole_game.sql`

Таблица `find_mole_cases`:

- `event_id` как PK и FK на `game_events`;
- публичная часть дела;
- секретное решение;
- версия шаблона;
- timestamps.

Таблица `find_mole_game_runs`:

- `id`, `event_id`, `user_id`;
- `token_hash`;
- `status`: `ready`, `won`, `failed`, `lost_race`, `expired`;
- выбранный suspect ID;
- `started_at`, `expires_at`, `completed_at`;
- `UNIQUE(event_id, user_id)`;
- индексы по `token_hash`, `(event_id, status)` и expiry.

### 4.2. Миграция `013_death_operation_game.sql`

Таблица `death_operation_game_runs`:

- `id`, `event_id`, `user_id`;
- `token_hash`;
- состояние подготовки и revision;
- hash снимка поставленной сети;
- одноразовый commit nonce;
- `status`: `preparing`, `armed`, `won`, `lost`, `lost_race`, `stale`,
  `expired`;
- `started_at`, `expires_at`, `armed_at`, `completed_at`;
- `UNIQUE(event_id, user_id)`.

Подготовка HTML5 хранится в новой таблице, но экономический результат остаётся
в `game_events`, `user_agents`, `event_participants` и `event_history`.

Текущий use case следует разделить на:

- `preview_death_operation`;
- `arm_death_operation`;
- `commit_death_operation`.

Telegram-кнопка и HTML5 вызывают один и тот же финальный repository-метод.

## 5. Telegram-интеграция

- Публиковать `find_mole` и `death_operation` через `sendGame`, когда включён
  соответствующий HTML5 flag.
- При отключённом HTML5 или ошибке `sendGame` публиковать Telegram fallback.
- После атомарного результата снимать клавиатуру исходного события.
- Итог отправлять отдельным сообщением в группу.
- Публично показывать только `@username`; использовать «Скрытый агент» только
  там, где метка участника необходима.
- LLM Narrator может оформить вводную и финал, но не получает право выбирать
  крота, roll, победителя, награду или срок.

## 6. Настройки и feature flags

Добавить независимые флаги, выключенные по умолчанию:

```dotenv
SPY_GAME_HTML5_MOLE_ENABLED=false
SPY_GAME_HTML5_DEATH_ENABLED=false
```

Общие `SPY_GAME_HTML5_URL`, `SPY_GAME_HTML5_SHORT_NAME=spies`, HTTP listener и
nginx остаются без изменений.

Предлагаемые typed settings:

```text
mole_game_run_seconds = 300
mole_suspect_count = 4
mole_reward_item_pool = все зарегистрированные предметы
mole_reward_amount = 1
mole_reward_agent_type = informant
mole_reward_agent_amount = 3
death_operation_game_run_seconds = 120
death_operation_commit_hold_seconds = 3
```

Экономические параметры Смертельной операции продолжают использовать текущие
settings: success percent, reward multiplier и bonus pool.

## 8. Обязательный test matrix

### Найти крота

- каждый шаблон имеет ровно одно решение;
- решение отсутствует в HTML и JSON;
- неправильный ответ не закрывает событие другим игрокам;
- один игрок не обвиняет повторно;
- два одновременных правильных ответа дают одну награду;
- сессия и персональный статус переживают restart;
- сюжет продвигается ровно один раз;
- повторный HTTP-запрос возвращает сохранённый результат.

### Смертельная операция

- до commit агенты не списываются;
- изменившийся состав возвращает `STALE_STAKE`;
- закрытие браузера и timeout не меняют баланс;
- двойной commit не повторяет списание или награду;
- параллельные commit дают один итог;
- ошибка SQLite откатывает событие, агентов и историю целиком;
- seeded success/failure сохраняют текущую экономику;
- Telegram fallback и HTML5 используют один resolver;
- restart не превращает подготовленную сессию в подтверждённую.

### Общие проверки

- миграции на чистой базе и upgrade существующей базы;
- серверная expiry и защита от client clock skew;
- неверные, просроченные и чужие bearer-токены;
- rate limit мутаций;
- отсутствие токенов и секретных решений в логах;
- отсутствие display name и numeric ID в публичном выводе;
- ровно одна строка истории на рассчитанное событие;
- отсутствие отрицательных балансов и повторных наград;
- полный Python regression suite и синтаксическая проверка JavaScript.

## 9. Наблюдаемость

Добавить структурированные события без секретных данных:

- HTML5 launch и game type;
- session started/expired/completed;
- mole accusation outcome;
- death operation armed/committed/stale;
- экономический outcome и idempotency result;
- ошибка публикации и переход на fallback.

Для beta отслеживать:

- долю launch -> start -> completion;
- среднее время расследования;
- долю правильных обвинений;
- долю подготовленных, но не подтверждённых Смертельных операций;
- фактический success rate Смертельной операции;
- число stale stake и lost race;
- изменение объёма агентов до и после релиза.

## 10. Beta rollout и rollback

1. Снять online backup SQLite через `.backup` и проверить
   `PRAGMA integrity_check`.
2. Доставить код с обоими новыми HTML5-флагами `false`.
3. Проверить старт, миграции, WAL, health и старые fallback-механики.
4. Включить «Найти крота» в одном allowlisted beta-чате.
5. Проверить правильный и неправильный ответ, конкурентную победу, награду и
   сюжетный переход.
6. После отдельного review включить Смертельную операцию.
7. Проверить подготовку без списания, stale snapshot, success, failure и
   idempotent repeat.
8. После ручного smoke разрешить естественный spawn и наблюдать метрики.

Rollback выполняется выключением отдельного feature flag и restart
`belmondo.service`. Миграции и данные не удаляются и не откатываются. Telegram
fallback остаётся доступен.

## 11. Решения перед началом реализации

Рекомендуемые значения для первого релиза:

1. В «Найти крота» у каждого игрока одна финальная версия.
2. Награда — случайный предмет x1 и `Осведомитель x3`, без Tier 3.
3. Подготовка Смертельной операции не меняет шанс 35%.

Если любое из этих решений меняется, сначала нужно пересчитать экономику и
скорректировать state machine и test matrix.
