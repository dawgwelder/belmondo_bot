# Архив особых заслуг, v1

Реализованы 36 достижений из согласованного каталога. Источник описаний,
стабильных ID, порогов и очков — `spy_game/achievements.py`. Каталог содержит
8 заслуг сети, 6 карьерных, 8 за смертельные операции, 9 за события/контакты
и 5 секретных. Очки косметические; любое открытое достижение доступно как титул.
Название службы «Центр — это вы» использует настроенный `agency_max_level`.
Репутация не имеет потолка: в каталоге отдельные рубежи 3, 5 и 10.

## Атомарный учёт

Миграция `014_achievements.sql` добавляет очередь фактов, постоянные максимумы
и счётчики, множества уникальных типов/соперников/контактов/тактик, выданные
достижения и выбранный титул. Уникальный ключ выдачи — `(user_id, achievement_id)`.

Триггеры записывают снимок доступного состава сети при изменении `user_agents`,
максимум репутации до/после сброса и уровень службы. Журналы `event_history`,
`economy_history`, `agency_history`, `spy_duel_history` добавляют ссылки на
новые факты. Это покрывает общую экономику и отдельный репозиторий дуэлей.

`SpyGameService` устанавливает общий callback `SQLiteDatabase.before_commit`.
Он вызывает `AchievementsRepository.drain` на том же соединении, до commit
каждой `immediate=True` транзакции. Слой SQLite не импортирует игровой каталог.
Награда, факт, максимум, достижение и удаление обработанного факта фиксируются
вместе. Исключение откатывает всё. Очередь читается порциями по 500 строк;
уже обработанная история на каждом клике не перечитывается. Обе роли одной
погони проверяются по индексу `(event_id, user_id)` в существующем журнале.

Сервисные чтения архива используют короткую транзакцию и предварительно
обрабатывают очередь. Титулы проверяются на сервере, а FK дополнительно
запрещает ссылаться на невыданную заслугу. Клиент не может передать прогресс,
очки или факт победы. Для HTTP используется личность из подписанного initData;
Telegram-кнопки страницы и титула привязаны к владельцу досье.

## Правила

- Размер сети — максимум подтверждённого одновременного состава, а не сумма
  всех приходов. Резервирование ставки не отнимает уже полученные заслуги.
- Коллекция учитывает все когда-либо подтверждённые типы; «Полный штат» —
  максимум числа типов, находившихся в одном снимке сети.
- Репутация и агентство сохраняют достигнутые максимумы после сбросов.
- Все победы смертельной операции считаются по единственному итоговому
  `event_history`, чтобы не удваивать итог из `death_mission_runs`.
- Личные победы, HP, пережитая облава и тактика проверяются по серверной
  завершённой миссии. «План Б» требует добровольного `extracted` с ненулевым
  возвратом; `timed_out` и пустая эвакуация не подходят.
- Дуэли учитывают только итог `moves` и уникального соперника. Сдача,
  таймаут, возврат ставки и повторная победа над тем же игроком не добавляют
  нового соперника.
- Совместная операция учитывается после награды, не после простого вклада.
  Кодовые тайники требуют `won`; inline-обыск считается только для пустого
  тайника. В перехвате учитываются успешные inline- и HTML5-результаты.
- Постоянные контакты требуют `source=operational_center`; удвоенный обмен
  редкой встречи имеет отдельный счётчик.
- «Пустой кабинет» фиксируется при повышении уровня службы, когда последний
  директор уже списан. «Возвращение резидента» требует поражения с нулевым
  доступным балансом, затем нового подтверждённого состава из 100 агентов.
  Доход, полученный во время личной миссии и оставшийся после поражения,
  не позволяет считать потерю полной.

## Перенос существующих данных

Одноразовая миграция ставит сохранившиеся журналы в очередь по времени, затем
текущий состав, репутацию, службу и снимки ставок активных личных миссий.
Из истории восстанавливаются победы, роли, сделки, репутация, развитие службы,
подтверждённые награды/расходы для коллекции и составы ставок смертельных
операций. Прежняя одновременная сеть без сохранённого снимка не выдумывается.
Не восстанавливаются прошлые «Пустой кабинет» и «Возвращение резидента»: старые
журналы не гарантируют полный баланс в нужный момент. Даты выдачи при переносе
отражают обработку доступных фактов, а не гарантированное историческое время
первого выполнения условия. Повторный запуск не пересчитывает выдачу.

## Интерфейсы и проверка

Telegram: новая кнопка `/spy`, шесть страниц по шесть достижений, редактирование
той же карточки при навигации, выбор/снятие титула, отметка прочитанными только
успешно показанных достижений. Mini App: раздел «Заслуги», счётчик в досье,
прогресс, выделение открытых заслуг от 50 очков, титул и явная отметка просмотра.
Уведомления — счётчик/значок в этих интерфейсах, без автоматической рассылки.

HTTP: `POST /spy-app/api/achievements/title` принимает `achievement_id` или
`null`; `POST /spy-app/api/achievements/seen` — список `achievement_ids`.
Они доступны из личного досье без привязки к чату, под общей авторизацией.
Закрытые секреты не отдают название, условие, числовой прогресс или записку.

```bash
PYENV_VERSION=3.12.4 pytest -q
node --test tests/test_death_mission_ui.js tests/test_spy_achievements_ui.js
node --check spy_game/webapp_static/app.js
git diff --check
```

Проверки включают транзакционный откат после выдачи, повторные/конкурентные
запросы, перезапуск, перенос БД версии 13, фактическое прохождение личной миссии,
различие all-in/личного режима/эвакуации, HTTP-подмену владельца, сокрытие секретов,
Telegram-навигацию и поведение поставляемого JS-контроллера.

Для серверного обновления нужна обычная остановка/перезапуск приложения после
резервной копии SQLite через online `.backup` и проверки `PRAGMA integrity_check`.
Миграция запускается при инициализации сервиса. Автоматическое понижение схемы
не предусмотрено. На сервер в рамках этой реализации изменения не выкатывались;
проверки реального Telegram и мобильного WebView остаются частью beta-проверки.
